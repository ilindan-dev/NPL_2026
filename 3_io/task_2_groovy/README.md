# 3.2 Groovy - валидатор конфигурационных .ini файлов с записью отчёта

Программа читает `.ini` (секции `[section]`, пары `ключ = значение`, комментарии `;`/`#`)
и проверяет:

- **синтаксис**: строка не является ни секцией, ни парой, ключ вне секции;
- **обязательные поля**: секции и ключи, помеченные `required` в схеме;
- **типы и диапазоны**: `int` (порт 1..65535), `float`, `bool`, `enum` (уровень логов),
  `string` с форматом (URL базы вида `схема://адрес`);
- **предупреждения**: повторные ключи, неизвестные секции и ключи.

Результат печатается в консоль, а ошибки **дописываются** в `error.log` с датой и временем.

## Запуск

`run.sh` монтирует репозиторий, поэтому `error.log` появится прямо в папке задачи.

```bash
./run.sh 3_io/task_2_groovy configs/good.ini                    # ошибок нет
./run.sh 3_io/task_2_groovy configs/bad.ini                     # куча ошибок
./run.sh 3_io/task_2_groovy configs/good.ini configs/bad.ini    # несколько файлов
cat 3_io/task_2_groovy/error.log
```

`*.log` есть в `.gitignore`, поэтому лог в коммит не попадёт.

## Как устроено

- **Схема** - обычная вложенная Groovy-мапа `секция → ключ → правило`
  (`[type: 'int', required: true, min: 1, max: 65535]`). Чтобы добавить поле, достаточно одной строки.
- **Разбор файла**: `readLines` + регулярные выражения Groovy (`=~`, `==~`).
  Для каждого ключа запоминается номер строки, чтобы ошибка указывала, где именно проблема.
  Срезаются хвостовые комментарии и кавычки вокруг значения.
- **`checkValue`** - `switch` по типу правила. Возвращает текст ошибки или `null`.
- **Отчёт**: `File.append(...)` дописывает в `error.log` блок «[дата] файл: ошибок N» и список ошибок.
- Код выхода 1, если есть ошибки. Это удобно для скриптов и CI.
