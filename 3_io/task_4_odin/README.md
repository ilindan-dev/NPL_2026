# 3.4 Odin — генератор надёжных паролей и хранилище

Программа спрашивает имя сервиса, длину пароля и требования (цифры, спецсимволы),
генерирует пароль криптографически стойким генератором, показывает его вместе с оценкой
стойкости и **дописывает** в файл `vault.txt`. Каждая запись там закодирована в Base64.
Есть просмотр хранилища, при котором записи декодируются обратно.

Код написан под **Odin dev-2024-12** (язык ещё развивается, версия в Dockerfile
зафиксирована). Официального Docker-образа у Odin нет, поэтому компилятор собирается
из исходников. Первая сборка займёт несколько минут, потом образ берётся из кэша.

## Запуск

```bash
./run.sh 3_io/task_4_odin                                # интерактивное меню
./run.sh 3_io/task_4_odin gen github.com 20              # сразу сгенерировать
./run.sh 3_io/task_4_odin gen bank.ru 12 --no-special
./run.sh 3_io/task_4_odin list                           # показать хранилище
cat 3_io/task_4_odin/vault.txt                           # как оно лежит на диске
```

> `vault.txt` — демонстрационный файл. Base64 — это кодирование, а не шифрование,
> поэтому настоящие пароли так хранить нельзя. Лучше не коммитить его в репозиторий.

## Как устроено

- **Случайность** — `crypto.rand_bytes`, системный криптографический генератор
  (а не обычный псевдослучайный, который можно предсказать).
- **`random_index(n)`** — равномерный выбор символа. Байт даёт 0..255, и если брать просто
  `байт % n`, некоторые символы выпадали бы чаще. Поэтому значения выше `256 - 256 % n`
  отбрасываются (rejection sampling).
- **`generate`**:
  1. алфавит собирается из включённых классов (строчные, заглавные, цифры, спецсимволы);
  2. из **каждого** класса берётся минимум один символ, так требования гарантированно выполнены;
  3. остальные символы берутся из общего алфавита;
  4. перемешивание **Фишера-Йетса**, чтобы обязательные символы не стояли в начале.
- **Стойкость**: энтропия = `длина × log2(размер алфавита)` бит.
- **Хранилище**: строка `сервис<TAB>пароль<TAB>дата` → `base64.encode` → дописывается в файл.
  `list` читает файл, декодирует каждую строку и печатает таблицу.
- Память: временные строки создаются в `context.temp_allocator`, который очищается
  `free_all` после каждой команды меню.

## Шпаргалка для видео

1. *«Задача 3.4 на Odin: генератор паролей с хранилищем в файле».*
2. Показать `random_index`: *«Используется криптографический генератор. Чтобы распределение было равномерным, лишние значения байта отбрасываются, иначе остаток от деления давал бы перекос».*
3. Показать `generate`: *«Собираем алфавит из выбранных классов, берём хотя бы по одному символу каждого класса, добиваем до нужной длины и перемешиваем алгоритмом Фишера-Йетса».*
4. Показать `save_entry`: *«Запись — сервис, пароль и дата через табуляцию, кодируем в Base64 и дописываем в конец файла».*
5. Интерактивный запуск: ввести сервис, длину, ответить на вопросы. *«Пароль и оценка стойкости в битах».*
6. `gen ... --no-special`, затем `list`: *«Хранилище декодируется обратно в таблицу».*
7. `cat vault.txt`: *«На диске только Base64-строки».*

## Возможные вопросы

- **Base64 — это шифрование?** Нет, это кодирование, обратимое без ключа. Задание допускает такой вариант. Для настоящего шифрования нужен ключ из мастер-пароля и, например, AES-GCM.
- **Почему не `math/rand`?** Обычный ГПСЧ детерминирован: зная состояние, можно предсказать пароли.
