# NPL 2026
Индивидуальная работа: 20 программ на 20 разных языках программирования. Пять тем, на каждую тему - по 4 программы. Специализированные тяжелые фреймворки не используются, упор на стандартные библиотеки (или минимально необходимые легковесные пакеты).

**Порядок работы**
Каждая задача делается в отдельной ветке. Имя ветки: `<номер темы>_task_<номер задачи>_<язык>`, например `4_task_1_kotlin`. Исходники лежат в папке своей темы: `<папка темы>/task_<номер>_<язык>/`.

**Выбранные языки (20 шт.):**
Rust, Nim, D, Elixir, Haskell, Prolog, OCaml, F#, Perl, Groovy, Zig, ODIN, Kotlin, Ruby, Lua, Swift, Clojure, Scala, Erlang, Julia.

### Тема 1. Многопоточность

**Папка:** `1_threads/`

| № | Задача | Язык | Ветка |
| --- | --- | --- | --- |
| 1 | Реализация паттерна Worker Pool для парсинга сетевых логов | Rust | `1_task_1_rust` |
| 2 | Конвейер Producer-Consumer для обработки игровых логов подземелий | Nim | `1_task_2_nim` |
| 3 | Параллельная сортировка пакетов данных («разделяй и властвуй») | D | `1_task_3_d` |
| 4 | Параллельное умножение матриц через акторную модель | Elixir | `1_task_4_elixir` |

* **1.1 Rust.** Реализация классического Worker Pool. Главный поток читает большой файл с диагностическими логами сетевой топологии, разбивает его на строки и отправляет через каналы (`mpsc`) пулу воркеров. Воркеры извлекают нужные метрики и складывают результаты в общий защищенный `Mutex` словарь.
* **1.2 Nim.** Паттерн Producer-Consumer. Несколько потоков-производителей читают файлы с событиями (логов прохождения подземелий) и помещают сырые события в потокобезопасную очередь. Потоки-потребители забирают события, агрегируют статистику урона/исцеления и выводят промежуточные итоги.
* **1.3 D.** Параллельная сортировка слиянием (Merge Sort). Массив структур (имитирующих сетевые пакеты с таймстемпами) рекурсивно делится пополам. Каждая сортировка запускается в отдельном потоке (через `core.thread` или `std.parallelism`). Главный поток дожидается выполнения и сливает отсортированные части.
* **1.4 Elixir.** Умножение больших матриц, где каждая строка результирующей матрицы вычисляется в отдельном легковесном процессе (акторе). Процессы обмениваются сообщениями. Демонстрируется изоляция состояний и отсутствие необходимости в классических мьютексах.

### Тема 2. Алгоритмические задачи

**Папка:** `2_algorithms/`

| № | Задача | Язык | Ветка |
| --- | --- | --- | --- |
| 1 | Поиск в глубину (DFS) для графа топологии (рекурсия) | Haskell | `2_task_1_haskell` |
| 2 | Быстрая сортировка (QuickSort) характеристик (рекурсия) | Prolog | `2_task_2_prolog` |
| 3 | Longest Repeating Character Replacement (LeetCode 150) | OCaml | `2_task_3_ocaml` |
| 4 | Search a 2D Matrix (LeetCode 150) | F# | `2_task_4_fsharp` |

* **2.1 Haskell.** Поиск компонент связности в неориентированном графе сетевой инфраструктуры. Граф задан списком смежности. Функция рекурсивно обходит узлы через алгоритм DFS, пробрасывая аккумулятор с посещенными вершинами, и возвращает список всех связанных подсетей.
* **2.2 Prolog.** Рекурсивная реализация QuickSort. На вход подается список числовых характеристик (например, уровней предметов). Предикат выбирает опорный элемент, рекурсивно разбивает список на элементы меньше и больше опорного, сортирует их и конкатенирует результат.
* **2.3 OCaml.** Алгоритмическая задача: найти длину самой длинной подстроки, состоящей из одинаковых букв, которую можно получить, заменив не более $k$ символов. Реализуется через паттерн "скользящее окно", но с использованием хвостовой рекурсии для прохода по строке.
* **2.4 F#.** Алгоритмическая задача: эффективный поиск целевого значения в отсортированной матрице $m \times n$. Поскольку строки отсортированы и начало каждой следующей строки больше конца предыдущей, задача решается через рекурсивный бинарный поиск, где матрица виртуально разворачивается в одномерный массив.

### Тема 3. Ввод/вывод в консоль и файл

**Папка:** `3_io/`

| № | Задача | Язык | Ветка |
| --- | --- | --- | --- |
| 1 | Аналог утилиты grep для фильтрации E2E тестов | Perl | `3_task_1_perl` |
| 2 | Интерактивный дневник изучения иностранных языков | Groovy | `3_task_2_groovy` |
| 3 | Консольная RPG-игра с сохранением инвентаря | Zig | `3_task_3_zig` |
| 4 | Анализатор CSV-партий с подсчетом винрейта дебютов | ODIN | `3_task_4_odin` |

* **3.1 Perl.** Консольная утилита, принимающая регулярное выражение и путь к файлу. Программа построчно читает лог работы системы непрерывной интеграции (CI), находит все строки с ошибками или запусками конкретных E2E тестов, подсвечивает совпадения цветом в консоли и выводит номер строки.
* **3.2 Groovy.** Консольное приложение для ведения заметок (например, новых слов из английского или немецкого). Команды вводятся с клавиатуры: добавление записи с текущей датой, поиск записей по дате или слову. Данные сохраняются в локальный текстовый файл и загружаются при старте.
* **3.3 Zig.** Простое текстовое приключение. Игрок перемещается по комнатам, собирает предметы в инвентарь и сражается. Текущее состояние (характеристики, список лута) сериализуется и сохраняется в бинарный или текстовый файл сохранения, позволяя продолжить игру после перезапуска.
* **3.4 ODIN.** Программа читает объемный CSV-файл с историей шахматных партий. Она парсит колонки с названиями дебютов (например, "Сицилианская защита") и результатами матчей. В конце в консоль выводится сводная таблица: количество сыгранных партий для каждого дебюта и процент побед белых/черных.

### Тема 4. Клиент-серверное взаимодействие

**Папка:** `4_client_server/`

| № | Задача | Язык | Ветка |
| --- | --- | --- | --- |
| 1 | Многопользовательский сервер текстового подземелья | Kotlin | `4_task_1_kotlin` |
| 2 | Умный Echo-сервер с балансировкой и маршрутизацией | Ruby | `4_task_2_ruby` |
| 3 | Удаленный калькулятор финансовых накоплений | Lua | `4_task_3_lua` |
| 4 | Сервер тестирования знаний с рассылкой вопросов | Swift | `4_task_4_swift` |

* **4.1 Kotlin.** Сервер на TCP-сокетах для игры в подземелье. Клиенты подключаются, отправляют команды перемещения (вверх, вниз, влево, вправо). Сервер держит в памяти карту, отслеживает координаты всех игроков и при движении одного из них рассылает обновленное состояние окружающим.
* **4.2 Ruby.** Сервер, имитирующий логику балансировщика нагрузки. Он принимает TCP-соединения, читает первые байты сообщения (заголовки/метаданные). В зависимости от настройки или ключевого слова в сообщении, сервер по-разному модифицирует ответ (например, оборачивает в JSON, переводит в верхний регистр) и отправляет обратно.
* **4.3 Lua.** Клиент-серверное приложение (через `luasocket`). Клиент отправляет на сервер команды с суммами доходов и расходов. Сервер поддерживает сессию пользователя, аккумулирует баланс и отвечает текущим состоянием счета и статистикой трат.
* **4.4 Swift.** Сервер на `Network.framework` (или `NIO`), который держит пул подключенных студентов. По команде администратора сервер рассылает клиентам вопросы теста. Клиенты отправляют ответы. Сервер проверяет их по эталону, ведет счет и по завершении отправляет каждому итоговый процент правильных ответов.

### Тема 5. Конвертация данных из одного формата в другой

**Папка:** `5_convert/`

| № | Задача | Язык | Ветка |
| --- | --- | --- | --- |
| 1 | Конвертер Markdown в HTML для документации | Clojure | `5_task_1_clojure` |
| 2 | Сериализация структуры PROTO (или её имитации) в JSON | Scala | `5_task_2_scala` |
| 3 | Парсер CustomTXT (правила лут-фильтра) в JSON | Erlang | `5_task_3_erlang` |
| 4 | Выгрузка конфигураций оборудования из JSON в CSV | Julia | `5_task_4_julia` |

* **5.1 Clojure.** Утилита, которая считывает файл с разметкой Markdown (заголовки `#`, списки `-`, жирный текст `**`). Функциональными преобразованиями текст разбивается на токены, из которых строится HTML-документ, который затем записывается в файл.
* **5.2 Scala.** Программа принимает бинарный файл или текстовое описание, имитирующее структуру Protobuf (с типизированными полями, вложенными сообщениями). За счет мощной системы типов и паттерн-матчинга Scala парсит эти данные и конвертирует их в человекочитаемый JSON.
* **5.3 Erlang.** Чтение кастомного текстового формата. В файле заданы блоки правил (например, правила подсветки предметов: `Class "Currency"`, `SetTextColor 255 255 255`). Erlang с помощью сопоставления с образцом разбирает эти блоки и перегоняет в структурированный массив JSON-объектов.
* **5.4 Julia.** Скрипт читает сложный, глубоко вложенный JSON-файл (например, список инвентарных номеров лабораторного оборудования, статусы бронирования, характеристики). Данные "уплощаются" (flatten) и выгружаются в строгий табличный формат CSV для последующего открытия в табличных процессорах.
