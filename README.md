# NPL 2026
Индивидуальная работа: 20 программ на 20 разных языках программирования. Пять тем, на каждую тему - по 4 программы. Специализированные тяжелые фреймворки не используются, упор на стандартные библиотеки (или минимально необходимые легковесные пакеты).

**Порядок работы**
Каждая задача делается в отдельной ветке. Имя ветки: `<номер темы>_task_<номер задачи>_<язык>`, например `4_task_1_kotlin`. Исходники лежат в папке своей темы: `<папка темы>/task_<номер>_<язык>/`.

**Выбранные языки (20 шт.):**
Rust, Nim, D, Elixir, Haskell, Prolog, OCaml, F#, Perl, Groovy, Zig, ODIN, Kotlin, Ruby, Lua, Swift, Clojure, Scala, Erlang, Julia.

Понял, виноват. Я исключил все задачи, которые упоминались в твоем тексте (включая Worker Pool, Producer-Consumer, крестики-нолики, эхо-серверы, DFS, grep, дневники и прочее).

Собрал 20 абсолютно новых задач. Учтены твои пожелания по языкам для клиент-сервера (Swift, Kotlin, Lua, Ruby) и конвертации (JSON->XML, PROTO->JSON, MD->HTML), алгоритмы взяты с LeetCode (2 рекурсивные, 2 итеративные). Языки с функциональной парадигмой сведены к базовому использованию, чтобы не требовалось глубокого погружения.

### Тема 1. Многопоточность

**Папка:** `1_threads/`
Здесь применяем базовые паттерны синхронизации, не дублируя классические примеры из твоих списков.

| № | Задача | Язык | Ветка |
| --- | --- | --- | --- |
| 1 | Пул потоков (Future/Promise): Параллельный пинг/сканирование URL | Rust | `1_task_1_rust` |
| 2 | Паттерн Map-Reduce: Параллельное применение фильтра к "изображению" | D | `1_task_2_d` |
| 3 | Read-Write Lock (Читатели-Писатели): In-memory кэш конфигураций | Nim | `1_task_3_nim` |
| 4 | Барьерная синхронизация (Barrier): Клеточный автомат | Ada | `1_task_4_ada` |

* **1.1 Rust.** Программа имитирует конкурентный чекер доступности сайтов. Главный поток создает очередь из 100 URL-адресов (строк). Пул из 4-5 рабочих потоков берет адреса, делает фиктивную задержку (`sleep`) и возвращает результат в главный поток.
* **1.2 D.** Паттерн Map-Reduce на массиве данных. Генерируется большой одномерный массив (имитация пикселей). Массив делится на чанки. Потоки параллельно проходят по своим чанкам, применяя математическую операцию (Map), после чего главный поток суммирует измененные значения (Reduce).
* **1.3 Nim.** Реализация многопоточного кэша с использованием блокировки чтения-записи (`RWMutex`). 10 потоков-читателей постоянно читают настройки из общего словаря, а 2 потока-писателя раз в несколько секунд обновляют эти настройки.
* **1.4 Ada.** Симуляция клеточного автомата (например, "Жизни" Конвея) на сетке. Сетка разбита на секторы. Каждый сектор обсчитывается своей задачей (task). Использование механизма "Барьер" (Barrier), чтобы потоки дожидались окончания хода у всех соседей, прежде чем перерисовать консоль и начать новый такт.

### Тема 2. Алгоритмические задачи (LeetCode)

**Папка:** `2_algorithms/`
Функциональные языки отлично подходят для алгоритмики. Задачи взяты с LeetCode.

| № | Задача | Язык | Ветка |
| --- | --- | --- | --- |
| 1 | Generate Parentheses (LeetCode 22) — *Рекурсия* | Prolog | `2_task_1_prolog` |
| 2 | Lowest Common Ancestor of a Binary Tree (LeetCode 236) — *Рекурсия* | F# | `2_task_2_fsharp` |
| 3 | Top K Frequent Elements (LeetCode 347) — *Итеративная* | Scala | `2_task_3_scala` |
| 4 | Container With Most Water (LeetCode 11) — *Итеративная* | OCaml | `2_task_4_ocaml` |

* **2.1 Prolog.** Классическая задача генерации правильных скобочных последовательностей (Backtracking). Логика Prolog идеально ложится на перебор с возвратом через рекурсивные правила.
* **2.2 F#.** Поиск наименьшего общего предка (LCA) в бинарном дереве. Дерево задается через алгебраические типы данных (Union Types). Функция рекурсивно спускается в левое и правое поддерево.
* **2.3 Scala.** Найти $k$ наиболее часто встречающихся элементов в массиве. Решается лаконично через встроенные методы коллекций (группировка, подсчет размера, сортировка) без мутации состояния.
* **2.4 OCaml.** Задача на паттерн "два указателя". Дан массив высот линий, нужно найти две линии, которые вместе с осью X образуют контейнер, вмещающий больше всего воды. Проход по массиву с двух сторон к центру.

### Тема 3. Ввод/вывод в консоль и файл

**Папка:** `3_io/`
Повседневные консольные утилиты.

| № | Задача | Язык | Ветка |
| --- | --- | --- | --- |
| 1 | CLI-генератор структуры директорий (аналог команды tree) | Perl | `3_task_1_perl` |
| 2 | Валидатор конфигурационных .ini файлов с записью отчета | Groovy | `3_task_2_groovy` |
| 3 | Консольный Pomodoro-таймер с логированием сессий | Zig | `3_task_3_zig` |
| 4 | Генератор надежных паролей и хранилище | ODIN | `3_task_4_odin` |

* **3.1 Perl.** Скрипт принимает путь к папке и рекурсивно обходит её, формируя в консоли красивое псевдографическое дерево вложенности папок и файлов.
* **3.2 Groovy.** Программа читает текстовый файл с настройками (ключ=значение), проверяет наличие обязательных полей и типы данных (например, порт должен быть числом). Ошибки валидации пишутся в отдельный `error.log`.
* **3.3 Zig.** Таймер для работы. В консоли идет обратный отсчет (с обновлением строки). По истечении времени программа издает звуковой сигнал (вывод `\a`) и дописывает в файл `stats.txt` дату и длительность отработанной сессии.
* **3.4 ODIN.** Приложение запрашивает у пользователя желаемую длину пароля и требования (цифры, спецсимволы). Генерирует строку, выводит её на экран и дописывает вместе с указанным именем сервиса в зашифрованный (или просто закодированный в Base64) текстовый файл-хранилище.

### Тема 4. Клиент-серверное взаимодействие

**Папка:** `4_client_server/`
Используем строго выбранные тобой языки.

| № | Задача | Язык | Ветка |
| --- | --- | --- | --- |
| 1 | Синхронизация общего списка задач (To-Do) в реальном времени | Kotlin | `4_task_1_kotlin` |
| 2 | Сервер-матчмейкер для "Камень-ножницы-бумага" | Ruby | `4_task_2_ruby` |
| 3 | TCP-заглушка API погоды | Lua | `4_task_3_lua` |
| 4 | Удаленный мониторинг состояния системы | Swift | `4_task_4_swift` |

* **4.1 Kotlin.** Сервер хранит в памяти список задач. Клиенты подключаются по TCP и отправляют команды: `ADD <task>`, `REMOVE <id>`. При любом изменении сервер широковещательно рассылает обновленный список всем подключенным клиентам.
* **4.2 Ruby.** Клиенты подключаются к серверу и ждут оппонента. Сервер берет два новых подключения, объединяет их в "комнату" и просит сделать ход (камень, ножницы или бумага). Получив ответы от обоих, сервер сообщает каждому результат (победа/поражение/ничья) и закрывает соединение.
* **4.3 Lua.** Простой сервер на `luasocket`. Клиент шлет текстовое название города. Сервер случайным образом генерирует температуру и погодные условия (дождь, солнце), упаковывает это в строку и возвращает клиенту.
* **4.4 Swift.** Программа-клиент отправляет запрос на сервер. Сервер (на `Network.framework`) собирает фиктивную статистику (или реальную, если API позволяет легко получить % загрузки CPU и свободную RAM) и возвращает клиенту отформатированный отчет.

### Тема 5. Конвертация данных из одного формата в другой

**Папка:** `5_convert/`
Взял форматы из твоих пожеланий + один дополнительный (YAML -> TOML).

| № | Задача | Язык | Ветка |
| --- | --- | --- | --- |
| 1 | JSON в XML | Elixir | `5_task_1_elixir` |
| 2 | PROTO-сообщения в JSON | Erlang | `5_task_2_erlang` |
| 3 | Markdown в HTML | Objective-C | `5_task_3_objc` |
| 4 | YAML в TOML | Julia | `5_task_4_julia` |

* **5.1 Elixir.** Программа читает валидный JSON-файл с объектами и массивами и рекурсивно переводит его в XML-теги с соблюдением отступов (pretty-print).
* **5.2 Erlang.** Парсер, который читает текстовое описание структуры данных, похожее на бинарный Protobuf (или самописный текстовый протокол с типами и значениями), и аккуратно собирает из этого стандартный JSON-объект.
* **5.3 Objective-C.** Конвертер, читающий `.md` файл. Программа распознает символы `**` (переводит в `<b>`), `#` (в `<h1>`), пустые строки (в `<p>`) и генерирует на выходе базовый HTML-документ.
* **5.4 Julia.** Парсинг простого подмножества формата YAML (без сложных вложенностей, базовые списки и словари) и запись этих же данных в формате TOML, соблюдая синтаксис ключей и секций.
