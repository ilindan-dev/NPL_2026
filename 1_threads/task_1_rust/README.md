# 1.1 Rust — пул потоков (Future/Promise): параллельный чекер URL

Главный поток создаёт 100 URL и отправляет их в пул из 4 рабочих потоков.
Рабочие берут адреса из общей очереди, имитируют проверку (`sleep` 30–330 мс,
всё дольше 280 мс считается таймаутом) и возвращают результат через Promise.
Только стандартная библиотека (`std::thread`, `std::sync::mpsc`, `Arc<Mutex<_>>`).

## Запуск (в Docker, из корня репозитория)

```bash
./run.sh 1_threads/task_1_rust            # 4 потока, 100 адресов
./run.sh 1_threads/task_1_rust 5          # 5 потоков
./run.sh 1_threads/task_1_rust 1 20       # 1 поток, 20 адресов (для сравнения)
```

Без скрипта:

```bash
docker build -t npl-task_1_rust 1_threads/task_1_rust
docker run --rm npl-task_1_rust 5
```

## Как устроено

- `ThreadPool::new(n)` — создаёт канал заданий и n рабочих; приёмник канала
  общий для всех, обёрнут в `Arc<Mutex<Receiver<Job>>>`.
- `pool.submit(f)` — кладёт замыкание в очередь и сразу возвращает `Promise<T>`
  (под капотом — отдельный одноразовый канал для результата).
- `promise.wait()` — главный поток блокируется, пока результат не готов.
- `Drop for ThreadPool` — закрывает очередь, рабочие выходят из цикла, `join()`.

В конце печатается статистика: сколько сайтов UP/DOWN/TIMEOUT, сколько адресов
обработал каждый рабочий и ускорение по сравнению с последовательной проверкой
(на 4 потоках ≈ x3.9).
