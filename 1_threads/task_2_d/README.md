# 1.2 D — Map-Reduce: параллельный фильтр "изображения"

Генерируется массив из 20 млн "пикселей" (яркость 0..255: градиент + шум).
Массив делится на чанки по числу потоков. Каждый поток применяет к своему чанку
фильтр (гамма-коррекция + контраст) - это **Map** - и считает частичную сумму.
Главный поток складывает частичные суммы - это **Reduce**.
Для сравнения то же самое считается в одном потоке. Только стандартная библиотека
(`core.thread`).

## Запуск

```bash
./run.sh 1_threads/task_2_d            # 4 потока, 20 млн пикселей
./run.sh 1_threads/task_2_d 1          # 1 поток - для сравнения
./run.sh 1_threads/task_2_d 8 50000000 # 8 потоков, 50 млн пикселей
```

## Как устроено

| Что | Где | Суть |
|---|---|---|
| `__gshared` массивы | начало файла | В D глобальные переменные по умолчанию свои у каждого потока (thread-local). `__gshared` делает их общими. |
| `filter` | | Чистая функция над одним пикселем. |
| `mapChunk` | | Map: фильтрует `[lo, hi)` и пишет сумму в `partial[id]`. Каждый поток пишет только в свою часть массивов, поэтому блокировки не нужны. |
| `makeTask` | | Создаёт делегат для потока. Через отдельную функцию, чтобы каждый поток получил свои `id/lo/hi`, а не общую переменную цикла. |
| `main` | | Запуск потоков `new Thread(...).start()`, ожидание `join()`, затем Reduce (сумма `partial`). Проверка, что результат совпал с однопоточным. |
