# 1.3 Nim - Read-Write Lock: in-memory кэш конфигурации

Общий словарь настроек (`Table[string, int]`). 10 потоков-читателей постоянно его читают,
2 потока-писателя раз в 2 секунды обновляют. Через RW-lock читатели работают
**одновременно**, а писатель получает **эксклюзивный** доступ.

В стандартной библиотеке Nim нет готового RWMutex, поэтому он собран вручную из
`Lock` и двух условных переменных `Cond` (модуль `std/locks`).

## Запуск

```bash
./run.sh 1_threads/task_3_nim             # с RW-lock - несогласованных чтений 0
./run.sh 1_threads/task_3_nim --nolock    # без блокировки - видно, что ломается
```

## Как устроено

- **RwLock** хранит количество читателей внутри (`readers`), флаг писателя (`writer`)
  и число ожидающих писателей (`waitingWriters`).
  - `acquireRead`: ждём, пока нет писателя и никто не ждёт записи, потом `readers += 1`.
  - `releaseRead`: последний вышедший читатель будит писателя (`signal(canWrite)`).
  - `acquireWrite`: ждём, пока нет ни читателей, ни другого писателя.
  - `releaseWrite`: будим **всех** читателей (`broadcast`) и одного писателя.
  - Приоритет у писателей: если писатель ждёт, новые читатели не заходят. Иначе при
    постоянном потоке читателей писатель никогда бы не дождался своей очереди (голодание).
- **Проверка согласованности.** Все настройки вычисляются из номера версии
  (`cache_ttl = v*10`, `max_connections = v*100`, ...). Писатель обновляет поля
  по одному, а между ними делает паузу 100 мс. Читатель проверяет, что все поля
  относятся к одной версии.
- `{.cast(gcsafe).}` нужен, чтобы компилятор Nim разрешил потокам обращаться к общему
  словарю. Безопасность этого доступа обеспечиваем сами блокировкой.
