# 1.4 Ada — барьерная синхронизация: «Жизнь» Конвея

Поле 24×60 разбито на 4 горизонтальных сектора, каждый сектор считает своя задача
(`task` в Ada — это поток). Чтобы посчитать новую клетку, нужны соседи, в том числе
из чужого сектора. Поэтому задачи синхронизируются **барьером**
(`Ada.Synchronous_Barriers`, стандарт Ada 2012): никто не начинает новый такт, пока
все не закончили текущий.

На экране живые клетки каждого сектора нарисованы своим символом (`# @ O %`), так видно,
какая задача за что отвечает.

## Запуск

```bash
./run.sh 1_threads/task_4_ada          # 150 поколений
./run.sh 1_threads/task_4_ada 50       # 50 поколений
```

## Как устроено

Два поля `Grids(0)` и `Grids(1)`: одно текущее (`Cur`), в другое пишется следующее
поколение. Один такт у каждой задачи:

1. Посчитать **свои** строки следующего поколения (читает текущее поле, пишет в другое).
2. `Wait_For_Release (Bar, Notified)` — **барьер 1**. Ждём, пока досчитают все 4 задачи.
3. Барьер сам выбирает ровно одну задачу (`Notified = True`). Она переключает `Cur`
   и рисует поле.
4. `Wait_For_Release` — **барьер 2**. Остальные ждут, пока отрисовка закончится.
   Без этого кто-то начал бы новый такт со старым значением `Cur`.

Задачи создаются через `new Worker (I)` и стартуют сразу. Процедура `Life`
автоматически ждёт завершения всех своих задач.

## Шпаргалка для видео

1. *«Задача 1.4 на Ada: барьерная синхронизация на примере игры "Жизнь"».*
2. Показать `Bar : Synchronous_Barrier (Release_Threshold => Workers)`: *«Барьер на 4 участника: он отпускает задачи, только когда до него дошли все четыре».*
3. Показать `task body Worker`: *«Каждая задача считает свой диапазон строк. Новое поколение пишется во второе поле, поэтому чтение и запись не мешают друг другу».*
4. *«Первый барьер: все досчитали. Барьер выбирает одну задачу через Notified, она меняет поколения местами и рисует. Второй барьер: все ждут отрисовку и начинают новый такт».*
5. Запуск: *«Справа подписано, какая задача считает какие строки, у каждого сектора свой символ. Фигуры спокойно переходят через границы секторов. Значит, задачи корректно видят результаты соседей».*

## Возможные вопросы

- **Почему два барьера, а не один?** После первого барьера одна задача меняет `Cur`. Если бы остальные сразу пошли считать, часть из них прочитала бы старое значение.
- **Почему нет гонок при записи в `Grids`?** Каждая задача пишет только в свои строки, а читает текущее поле, которое в этой фазе никто не меняет.
