# 5.4 Julia — конвертер YAML → TOML

Программа разбирает простое подмножество YAML и записывает те же данные в TOML,
соблюдая синтаксис ключей и секций.

```yaml
server:                          [server]
  host: 0.0.0.0                  host = "0.0.0.0"
  port: 8080            →        port = 8080
  tls:                           
    enabled: true                [server.tls]
                                 enabled = true
workers:
  - name: email                  [[workers]]
    threads: 4                   name = "email"
                                 threads = 4
```

Поддерживается: словари по отступам, списки `- `, списки словарей, инлайн `[a, b]` и
`{a: 1}`, строки в двойных и одинарных кавычках и без них, int, float, bool, null, даты,
комментарии `#`, ключи в кавычках. Многострочные строки (`|`, `>`), якоря и ссылки
(`&`, `*`) не поддерживаются, по заданию они не нужны.

## Запуск

```bash
./run.sh 5_convert/task_4_julia examples/config.yaml                       # TOML в консоль
./run.sh 5_convert/task_4_julia examples/config.yaml examples/config.toml  # в файл
./run.sh 5_convert/task_4_julia examples/broken.yaml                       # ошибка отступа
```

## Как устроено

**1. Чтение YAML** — свой парсер на основе отступов:
- `read_lines` убирает комментарии (кроме `#` внутри кавычек) и пустые строки. Для каждой
  строки запоминает номер и отступ;
- `parse_block` смотрит на первую строку: начинается с `- ` — список (`parse_list`),
  иначе словарь (`parse_map`);
- `parse_map` читает `ключ: значение`, пока отступ равен текущему. Пустое значение
  с более глубоким отступом ниже — вложенный блок (рекурсия);
- элемент `- name: email` — это словарь, ключи которого стоят на 2 пробела правее:
  строка подменяется и разбирается как обычный словарь;
- `parse_scalar` определяет тип значения: кавычки, `[...]`, `{...}`, null, bool, число, дата.

Порядок ключей важен для читаемого результата, поэтому словарь хранится в своём типе
`OMap` (вектор пар), а не в `Dict`.

**2. Запись TOML (`write_table`)** — рекурсивно по уровням:
- сначала простые `ключ = значение`. В TOML они обязаны идти до подтаблиц, иначе
  попадут не в ту секцию;
- вложенный словарь → секция `[родитель.ключ]`;
- список словарей → массив таблиц `[[ключ]]`, по заголовку на элемент;
- `null` в TOML не существует → пишется комментарий `# key = null (...)`;
- ключи с пробелами берутся в кавычки, строки экранируются.

Методы выбираются по **multiple dispatch**: `toml_value(x::Bool)`, `toml_value(x::Integer)`,
`toml_value(x::AbstractVector)`... Julia сама выбирает нужный метод по типу значения.

**3. Самопроверка.** Результат читается обратно стандартным парсером `TOML.parse` из
библиотеки Julia и сравнивается с исходными данными.

## Шпаргалка для видео

1. *«Задача 5.4 на Julia: конвертер YAML в TOML. YAML-парсер свой, для простого подмножества».*
2. Показать `parse_map`/`parse_list`: *«YAML описывает вложенность отступами. Парсер рекурсивный: блок на одном отступе — это словарь или список, а более глубокий отступ — вложенный блок».*
3. Показать `parse_scalar`: *«Тип значения определяется по виду: кавычки — строка, true/false — bool, цифры — число, формат год-месяц-день — дата, которая в TOML тоже станет датой».*
4. Показать `write_table`: *«В TOML вложенный словарь становится секцией в квадратных скобках, а список словарей — массивом таблиц в двойных скобках. Простые ключи пишутся раньше подтаблиц, это требование синтаксиса».*
5. Показать методы `toml_value`: *«Значения форматируются через multiple dispatch: свой метод для каждого типа».*
6. Запуск на `config.yaml`: *«Секции server и server.tls, массив таблиц workers, инлайн-таблица pool, null превратился в комментарий. Внизу самопроверка: стандартный TOML-парсер прочитал результат, данные совпали».*
7. `broken.yaml`: *«При ошибке отступа показывается номер строки».*

## Возможные вопросы

- **Почему не пакет YAML.jl?** По заданию упор на стандартную библиотеку. TOML-парсер же в стандартной библиотеке Julia есть, и он используется для проверки.
- **Куда делся null?** В TOML нет null: ключ либо есть, либо его нет. Поэтому он пропускается с комментарием.
