# 4.3 Lua - TCP-заглушка API погоды (luasocket)

Простой сервер на `luasocket`. Клиент шлёт название города строкой, сервер случайно
генерирует температуру и погодные условия, упаковывает их в строку и возвращает:

```
Москва
OK Москва: +12°C, дождь, ветер 5 м/с, влажность 80%
```

Сервер **однопоточный**, но обслуживает много клиентов одновременно через
`socket.select()`. Для одного города ответ стабилен в течение минуты (кэш), как у
настоящего API.

## Запуск (порт 5003)

```bash
# терминал 1 - сервер
./run.sh 4_client_server/task_3_lua server

# терминал 2 - интерактивный клиент
./run.sh 4_client_server/task_3_lua client

# разовые запросы
./run.sh 4_client_server/task_3_lua client localhost 5003 Москва Казань Сочи
```

Или `nc localhost 5003` и ввод городов вручную.

## Как устроено

**Протокол** - текстовый, по строке: запрос `<город>\n`, ответ `OK <погода>\n` или
`ERROR <причина>\n`. `QUIT` закрывает соединение.

**Сервер (`run_server`)**
- `socket.bind("*", port)` - слушающий сокет.
- Главный цикл: `socket.select({server, клиенты...})` блокируется, пока какой-нибудь сокет
  не станет готов к чтению:
  - готов `server`, значит пришёл новый клиент: `accept()`, добавить в список;
  - готов клиент, значит пришла строка: `receive("*l")`, ответить. `nil` означает,
    что клиент отключился, убираем его.
- Так один поток обслуживает всех: никто не блокирует остальных, пока молчит.
  Это мультиплексирование ввода-вывода, тот же принцип, что у nginx и Node.js.
- `get_weather` - кэш `[город] = {text, time}`: новая случайная погода генерируется
  не чаще раза в минуту.

**Клиент** - `socket.connect`, затем либо города из аргументов, либо цикл чтения с клавиатуры.
