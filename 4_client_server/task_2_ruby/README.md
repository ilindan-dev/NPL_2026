# 4.2 Ruby — сервер-матчмейкер для «Камень-ножницы-бумага»

Клиенты подключаются к серверу и встают в очередь. Сервер берёт двух игроков,
объединяет их в **комнату** и просит сделать ход. Получив ходы обоих, сообщает каждому
результат (победа / поражение / ничья) и закрывает соединение. Комнат может быть
сколько угодно одновременно. Используется только стандартная библиотека
(`socket`, `Thread`, `Queue`).

## Запуск (порт 5002)

```bash
# терминал 1 — сервер
./run.sh 4_client_server/task_2_ruby server

# терминал 2 и 3 — игроки (ход: к / н / б или камень / ножницы / бумага)
./run.sh 4_client_server/task_2_ruby client

# бот, ходит случайно — удобно, чтобы играть одному
./run.sh 4_client_server/task_2_ruby client localhost 5002 --bot
```

Можно и через `nc localhost 5002`.

## Как устроено

**Сервер**
- Главный поток: `server.accept` в цикле, каждый новый игрок кладётся в `Queue`
  (потокобезопасная очередь из стандартной библиотеки).
- **Поток-матчмейкер**: `waiting.pop` блокируется, пока в очереди никого нет. Берёт двоих.
  Если кто-то успел отключиться, пока ждал (`alive?`), его пропускает. Для пары создаёт
  комнату в **отдельном потоке**, поэтому игры идут параллельно.
- **Комната (`play`)**:
  1. сообщает обоим о сопернике и просит ход. Если один уже отвалился, второго
     возвращает в очередь;
  2. читает ходы **параллельно** (по потоку на игрока, `Thread#value` ждёт результат),
     так что никто не ждёт, пока сходит другой. На неверный ввод даётся до 3 попыток;
  3. считает результат через таблицу `BEATS` (кто кого бьёт), рассылает его и закрывает
     соединения (`ensure`).

**Клиент** — один поток с `IO.select`: ждёт данных одновременно от сервера и с клавиатуры.
В режиме `--bot` на приглашение «Ваш ход» сам отвечает случайным ходом.

## Шпаргалка для видео

1. *«Задача 4.2 на Ruby: матчмейкер для камень-ножницы-бумага».*
2. Показать `run_server`: *«Главный поток принимает подключения и ставит игроков в потокобезопасную очередь Queue. Отдельный поток-матчмейкер забирает их по двое и для каждой пары создаёт комнату в своём потоке».*
3. Показать `play`: *«В комнате оба получают приглашение, ходы читаются параллельно, каждый в своём потоке. Потом результат по таблице "кто кого бьёт", и соединения закрываются».*
4. *«Обработаны отключения: если игрок ушёл до начала игры, второго возвращаем в очередь».*
5. Демо: сервер + два ручных клиента, сыграть. Затем 4 бота сразу: *«Видно, что комнаты создаются параллельно, сервер пишет лог по каждой комнате».*
6. Подключить одного клиента и закрыть его, затем подключить двух ботов: *«Сервер это заметил и не поставил отключившегося в пару».*

## Возможные вопросы

- **Зачем `Queue`, а не массив?** `Queue#pop` блокирует поток, пока нет элементов, и безопасна для нескольких потоков. Не нужен ни свой мьютекс, ни активное ожидание.
- **Почему ходы читаются в потоках?** `gets` блокирующий. Если читать по очереди, первый игрок тормозил бы второго, а при его отключении зависла бы вся комната.
